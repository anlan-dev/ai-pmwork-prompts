# Prompt 调优指南 · AI 产品助理实战手册

> 创建日期：2026-06-06
> 适用场景：产品经理日常工作流中的 AI 对话优化
> 核心理念：**只写自己确认的东西，不过度补全，不让 AI 替你编造**

---

## 一、当前 AI 提示词现状评估

### 现有套件（6步骤全流程）
| 步骤 | 用途 | 评估 |
|:----:|------|:----:|
| ⓪ 需求梳理 | 录音→结构化需求 | ✅ 有效，但注意AI会过度脑补未提及的内容 |
| ① 截图转PRD | 竞品截图→功能提取 | ⚠️ 6.5已叫停：Figma拉框比AI截图高效 |
| ② 提取设计规范 | 截图→设计系统 | ⚠️ 同上，被叫停 |
| ③ 重构PRD | 旧PRD+新规范合并 | 🟡 可用但需严格执行"有什么写什么" |
| ④ 重构文案 | 差异化改写 | 🟡 可用 |
| ⑤ 融合输出GM | 文案+PRD合并输出 | 🟡 可用 |
| ⑥ 评审自查 | AI扫描遗漏 | ✅ 有效，但需人工二次确认 |

### 核心问题（来自6.5工具规范会议）
1. **过度依赖AI导致效率下降** — 截图处理10分钟 vs Figma拉框1分钟
2. **AI会编造** — "多维度视觉叠加"等产品经理自己都不懂的术语
3. **过度补全** — AI会脑补不存在的功能逻辑
4. **自动化陷阱** — 花时间搭AI自动流程 > 花时间做实际工作

## 二、Prompt 调优原则

### 原则1：精准约束 — 防止AI编造

```
❌ 差："帮我补充这个页面的所有交互逻辑"
✅ 好："只基于以下已知信息描述交互。不知道的写'待确认'"

❌ 差："分析用户在这个场景下的行为"
✅ 好："如果你需要编造用户行为数据来回答，请先告诉我'这个信息目前没有'"
```

### 原则2：强制透明 — AI必须暴露不确定性

```
每条提示词末尾追加：
"对于以上回答中你不确定、没有原始数据支撑、或属于推测的内容，请用【待确认】标记"
```

### 原则3：限定范围 — 不写"什么都要"的prompt

```
❌ 差："生成一份完整的PRD，包括所有章节"
✅ 好："只写当前确认的功能模块【模块A】和【模块B】的交互逻辑。其他模块留空"
```

### 原则4：结果导向 — 先有再优

```
参照"做到哪写到哪"策略，不追求一次完美的PRD。
prompt应引导AI聚焦：当前要交付的功能 → 精确描述 → 评审修正 → 迭代
```

## 三、PM 场景 Prompt 模板库

### 模板1：写精确的PRD段落（推荐替代全流程）

```text
你是一个精确、严谨的产品文档助理。

你的任务是帮我写一段PRD内容。规则：
1. **只写我提供的信息**。不准编造、不准脑补、不准过度补全。
2. **每写完一个功能点，用【已确认】或【待确认】标记**信息确定性。
3. **交互要精确到**：进入后的默认页面、默认按钮、点击后的目标页面。
4. **写清楚为什么**这样设计（用户习惯/降低认知负荷/Fitts法则/竞品参考/用户反馈）。
5. **不写你也不确定的术语**。如果你需要编造概念来完成回答，请先问我。

以下是我确认的信息：
【粘贴你确认的交互信息】
```

### 模板2：从录音提取精确需求

```text
从以下录音文本中提取需求，规则：
1. 只提取说话人 **明确拍板/确认** 的决策
2. 模糊的讨论、推测、未确认的提议 → 放入【待确认】区
3. 不要补全上下文、不要脑补决策原因
4. 每个需求标注：说话人、确定性（已确认/待确认）

录音文本：
【粘贴录音文本】
```

### 模板3：检查PRD歧义

```text
作为严格的PRD评审员，检查以下PRD段落：

1. 标记所有 **开发无法直接执行的描述**（模糊、歧义、缺少量化）
2. 标记所有 **产品经理自己可能都不理解的概念**
3. 标记所有 **没有体现在文档中的默认页面/默认按钮/默认状态**
4. 标记所有 **缺少异常处理描述** 的地方

PRD内容：
【粘贴PRD段落】
```

### 模板4：BIP漂流瓶内容策划

```text
帮我策划一条Build in Public内容（产品开发日记），规则：
1. 只基于我的实际工作经历，不编造
2. 语气真诚，像开发者在记录真实过程
3. 围绕一个问题展开：今天解决了什么/学到了什么/遇到了什么有趣的事
4. 200-300字，适合社交媒体发布

以下是真实素材：
【粘贴你今天的实际工作】
```

## 四、Prompt 自检清单

发prompt前问自己：

| 问题 | 自检 |
|------|:----:|
| 这个prompt会让AI编造我不知道的东西吗？ | ⬜ |
| 有没有明确告诉AI "不知道就说不知道"？ | ⬜ |
| 输出的范围是否精确控制了？ | ⬜ |
| 是否要求AI标注信息来源的确定性？ | ⬜ |
| 如果不满意AI的输出，是因为prompt不够精确还是AI本身不会？ | ⬜ |
| 这件事花10分钟做AI vs 1分钟手动做，哪个更值？ | ⬜ |

---

## 五、一句话总结

> **让AI做助手，不是做替身。你不确认的事，AI也不该替你写。**
