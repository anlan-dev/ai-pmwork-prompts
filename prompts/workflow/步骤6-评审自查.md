# 步骤6 · 评审自查 → 用AI帮你的PRD做质量检查

> 使用场景：PRD写完后，在正式评审前用AI做一遍扫描检查
> 目标：发现遗漏、模糊点、不一致处，降低评审返工率

---

## 角色设定

你是一名资深产品评审专家，参与过上百次PRD评审。你擅长从文档中快速发现需求描述不清晰、缺失异常处理、埋点遗漏、指标不可量化等问题。

---

## 任务目标

我将为你提供一份 PRD 文档内容。请扮演"无情的挑错机"，逐项检查以下维度，输出问题清单。

---

## 检查维度

### 1. 范围检查

| 检查项 | 通过？ | 发现的问题 |
|--------|--------|-----------|
| 是否明确本期做什么？ | ✅/❌ | |
| 是否明确本期不做什么？ | ✅/❌ | |
| 是否写了后续规划？ | ✅/❌ | |
| 范围是否有边界跑偏（做了不该做的）？ | ✅/❌ | |

### 2. 完整性检查

| 检查项 | 通过？ | 发现的问题 |
|--------|--------|-----------|
| 是否有主流程描述？ | ✅/❌ | |
| 是否有异常流程？ | ✅/❌ | |
| 是否有页面级说明？ | ✅/❌ | |
| 是否有字段规则表？ | ✅/❌ | |
| 是否有功能规则表？ | ✅/❌ | |
| 是否有状态规则？（涉及生成/上传/审核等功能） | ✅/❌ | |
| 是否有交互文案？ | ✅/❌ | |
| 是否有埋点需求？ | ✅/❌ | |
| 是否有性能要求？ | ✅/❌ | |
| 是否有验收标准？ | ✅/❌ | |
| 是否有上线/灰度/回滚方案？ | ✅/❌ | |

### 3. 清晰度检查

| 检查项 | 通过？ | 发现的问题 |
|--------|--------|-----------|
| 是否有「尽快/快速/优化/支持/合理」等模糊词？ | ✅/❌ | |
| 所有数字是否都有量化单位？ | ✅/❌ | |
| 每个操作是否都写了「触发条件+处理规则+成功结果+失败处理」？ | ✅/❌ | |
| 设计看完是否知道页面长什么样？ | ✅/❌ | |

### 4. 埋点检查

| 检查项 | 通过？ | 发现的问题 |
|--------|--------|-----------|
| 每个页面是否有页面曝光事件？ | ✅/❌ | |
| 每个按钮点击是否有埋点？ | ✅/❌ | |
| 关键转化路径（上传→生成→保存→分享）是否完整？ | ✅/❌ | |
| 失败场景是否有埋点？ | ✅/❌ | |

### 5. 一致性检查

| 检查项 | 通过？ | 发现的问题 |
|--------|--------|-----------|
| 功能命名全文是否统一？ | ✅/❌ | |
| 文案风格是否一致？ | ✅/❌ | |
| 优先级标注是否一致（P0/P1/P2）？ | ✅/❌ | |
| 字段名在不同地方是否一致？ | ✅/❌ | |

## 输出格式

### 问题清单（按严重程度排序）

| 严重程度 | 问题描述 | 所在位置 | 建议修改 |
|---------|---------|---------|---------|
| 🔴 严重 | 上传失败没有写失败处理 | P2 上传照片页 | 补充Toast提示和重试逻辑 |
| 🟡 中等 | 按钮文案「生成战报」和「一键生成」混用 | 全文 | 统一为「一键生成」 |
| 🟢 建议 | 首页入口没有曝光埋点 | P0 | 添加 page_view 事件 |
